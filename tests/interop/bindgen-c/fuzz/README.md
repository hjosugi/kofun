# bindgen-c adversarial macro corpus

The committed inputs and the seeded mutation fuzzer behind
[#901](https://github.com/kofun-lang/kofun/issues/901). Everything here is data:
no case is generated at run time from a clock, a PID, or an entropy source,
and nothing is fetched.

```sh
sh tests/interop/bindgen-c/check-fuzz.sh
```

## The contract every input is held to

For every header — committed or mutated — `kofun bindgen-c` must do exactly
one of two things:

| Outcome | What must be true |
|---|---|
| **accept** | exits 0; two runs over the same bytes produce byte-identical files; the generated bytes fit the output bound |
| **refuse** | exits with the tool's refusal code 2; stderr names a cause; **no `--out-dir` exists afterwards** |

Anything else is a defect and fails by name: a hang (the driver's own
watchdog fires before the tool's bound does), a crash (a signal, or an exit
code the tool never produces), a refusal with an empty stderr, a partial
`--out-dir`, output past the byte bound, or two runs of one input disagreeing.

## The bounds

Each is a constant. None is derived from the input, so the same header always
meets the same bound.

| Bound | Value | Where |
|---|---|---|
| clang wall clock, per subprocess | 20 000 ms | `tooling/bindgen-c/bindgen-c.mjs` |
| captured clang stdout, AST | 128 MiB | same |
| captured clang stdout, preprocessor | 64 MiB | same |
| captured diagnostic, relayed | 4 KiB | same |
| top-level declarations walked | 4096 | same |
| typedef chain depth | 32 | same |
| bindable identifier length | 128 | same |
| fuzz seed | `0x6b626669` | `fuzz-macros.mjs` |
| mutation cases | 32 | same |
| mutations per case | 3 | same |
| mutated header size | 96 KiB | same |
| generated bytes per case | 8 MiB | same |
| driver watchdog, per case | 45 000 ms | same |
| whole-run wall clock | 600 000 ms | same |

The driver's watchdog is deliberately *above* the tool's own clang bound. A
watchdog kill is therefore never ambiguous: it means the tool failed to bound
itself, which is the defect, not the test.

## The committed corpus

| File | What it attacks | Outcome here |
|---|---|---|
| `deep-object-macros.h` | 64 levels of nested object-like macros before a single token | accept |
| `self-referential.h` | directly self-referential and mutually recursive macros, object-like and function-like | accept |
| `token-paste.h` | `##` and `#` abuse: pastes nested in paste arguments, stringized pastes, a paste producing a keyword. No declarator name appears literally in the file | accept |
| `long-identifiers.h` | identifiers at 127 and 207 characters — both sides of the 128-character cap — plus a macro expanding to a 64-parameter list and a 4000-character literal | accept |
| `deep-typedef-chain.h` | a 48-link typedef chain, past the 32-link walk bound, alongside a shallow alias that stays bindable | accept |
| `paste-invalid-token.h` | `##` producing something that is not a preprocessing token | refuse: clang |
| `partial-declaration.h` | macros expanding to an unterminated `struct {` and an unclosed parameter list | refuse: clang |
| `hostile-diagnostic.h` | `#error` whose text is shell metacharacters, backticks, `$( )`, and `../..` | refuse: clang |
| `declaration-flood.h` | a paste flood expanding to 4352 top-level declarations | refuse: declaration bound |
| `fanout-expansion.h` | one macro use expanding to 8^5 tokens, folded into an enum constant | refuse: captured-output bound |

The last two are the interesting ones: they are refused by *this tool's*
bounds rather than by clang, which is what those bounds exist for. The
fan-out case is not theoretical — its JSON AST passes 128 MiB.

`hanging-clang.sh` is not a header. It is a stand-in compiler that never
answers, passed through the tool's own `--clang` option, and it is how the
wall-clock bound is exercised: a header that reliably diverged the real clang
would be a clang bug report rather than a fixture.

## The mutations

Ten pure functions of `(lines, random)`, each applied three times per case to
a corpus file chosen by the same seeded generator: duplicate a `#define`,
make a macro self-referential, inject `##`, inject `#`, lengthen an
identifier by 64–263 characters, truncate the file mid-declaration, drop a
line, repeat a line up to 31 times, swap two lines, and append a mutually
recursive macro pair built from names already in the file.

None of them consults anything outside its arguments, so the sequence of
mutations is a function of the seed alone.

## Reproducing a failure offline

The driver prints one line per case: `case`, its number, the corpus file and
mutation sequence it came from, and the outcome. With the seed fixed, case
`017` is the same header on every machine. To rebuild it by hand, apply the
named mutations in order to the named corpus file — or run the driver with a
work directory you keep:

```sh
node tests/interop/bindgen-c/fuzz/fuzz-macros.mjs \
    ./bin/kofun tests/interop/bindgen-c/fuzz/corpus /tmp/kbfuzz
```

Every mutated header stays at `/tmp/kbfuzz/case-NNN/kbfuzz.h`.

## What this corpus does not claim

It does not claim clang is safe on arbitrary input, and it does not fuzz
clang — it fuzzes the *boundary this repository owns*: whether `kofun
bindgen-c` stays deterministic, bounded, and honest about failure when the
header is hostile. Nothing here binds a new C construct, changes what is
generated, or weakens the `raw-trusted-foreign` marking on the output.
