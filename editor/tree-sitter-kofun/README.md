# tree-sitter-kofun

Incremental parser and editor queries for the
[Kofun programming language](https://github.com/hjosugi/kofun).

The grammar follows `spec/grammar.ebnf` and the accepted sources under
`examples/` and `tests/kofun/`. It keeps newlines significant at statement
boundaries, permits newlines inside parentheses and brackets, and supports both
trailing-operator continuation and the Stage 0 leading-`|>` continuation. The
current repository extensions for imports, the native CLI profile, and the C
ABI profile are represented by named syntax nodes.

## Development

Node.js 20 or newer is required. The lockfile pins the Tree-sitter CLI.

```sh
npm ci
npm test
npm run test:repository-corpus
npm run test:queries
```

`npm test` regenerates the parser, runs the focused corpus, and
checks that incomplete declarations, expressions, and delimiters retain useful
named recovery structure. The repository-corpus test requires every `.kofun` file below
`examples/` and `tests/kofun/` to parse without an error or missing node.

## Editor integration

The package declares the `source.kofun` scope and `.kofun` file type in
`tree-sitter.json`. Its standard queries are:

- `queries/highlights.scm`
- `queries/locals.scm`
- `queries/indents.scm`
- `queries/folds.scm`

For Neovim, point a parser configuration at this repository and use
`editor/tree-sitter-kofun` as its grammar location, then install or update the
`kofun` parser. Copy or link the four query files into
`queries/kofun/` in the Neovim runtime path when the parser manager does not
discover package queries automatically.

For Helix, add a `[[grammar]]` entry named `kofun` that resolves to this
repository and set `source.path = "editor/tree-sitter-kofun"`. Add a language
entry with `scope = "source.kofun"`, `file-types = ["kofun"]`, and
`grammar = "kofun"`. Copy or link the query files into
`runtime/queries/kofun/`.

The indent query emits both Helix-style `@indent` / `@outdent` captures and
Neovim-style `@indent.begin` / `@indent.end` captures.

## Generated sources

`src/parser.c`, `src/grammar.json`, and `src/node-types.json` are generated by
the pinned CLI and are committed so editor integrations do not need Node.js to
compile the parser. Run `npm run generate` after changing `grammar.js`, and
then run all three validation commands above.

This package provides syntax, highlighting, local-scope, indentation, and fold
structure only. Semantic name resolution, type-aware highlighting, and LSP
features remain outside its scope. Identifiers intentionally use the ASCII
bootstrap token profile; the broader Unicode-identifier design is not yet an
executable accepted-source requirement.
